The __free_hook tombstone

2.34 didn't delete the hooks — it stopped calling them (malloc.c references 5 → 0). The symbols still ship for ABI compat, so pwntools resolves them and you can overwrite the slot. Nothing reads it. The exploit dies against a symbol that's right there.

$ nm -D libc.so.6 | grep _hook   # glibc 2.39
0000000000020a148 V __free_hook@GLIBC_2.2.5
0000000000020a140 V __malloc_hook@GLIBC_2.2.5
# overwrite it → nothing happens. it's a decoy.

The unsorted‑bin attack died in 2.28 ✱

Nearly every writeup bundles it with the 2.29 tcache key. But the bck->fd != victim guard at the "remove from unsorted list" site is absent in 2.27, present in 2.28. The write primitive was already dead a release earlier than the folklore says.

// glibc 2.28 _int_malloc, unsorted loop
if (__glibc_unlikely (bck->fd != victim))
  malloc_printerr("corrupted unsorted chunks 3");
unsorted_chunks(av)->bk = bck;
bck->fd = unsorted_chunks(av);  // the old write
